## Memory Search And Agent Architecture

### 1. Thinking Process와 Test-Time Scaling

메모는 최근 흐름을 **추론 시점의 확장**으로 본다.

- **Test-Time Scaling**
  - 학습보다 추론 엔진 중심으로 확장
  - 외부 도구 시스템과 분리해 생각할 수 있음

여기서 강조하는 감각은:

- 프롬프트만 잘 쓰는 문제가 아니라
- 추론 아키텍처 자체를 설계하는 문제로 넘어가고 있다는 점이다

### 2. 메모리 사용량과 숨은 비용

추론을 길게 하거나 복잡하게 만들수록 메모리 부담도 커진다.

메모에서 짚은 핵심은 두 가지다.

- **KV Cache 누적**
- **hidden tokens 대량 사용**

즉, "생각을 더 많이 하게 만들수록 항상 좋은가?"라는 질문과 함께, **추론 비용과 메모리 비용**도 같이 봐야 한다.

### 3. Short-term / Long-term Memory

메모는 메모리도 계층적으로 정리한다.

- **Short-term memory**
  - `HBM Local`

- **Long-term memory**
  - `SSD`, `NAND`

이 구분은 에이전트 시스템을 설계할 때 중요하다.

- 당장 빠르게 참조할 메모리
- 오래 저장하고 다시 꺼내 쓸 메모리

를 분리해서 생각해야 하기 때문이다.

### 4. Agentic AI 아키텍처

메모는 Agentic AI 구조를 네 단계로 정리한다.

1. **인지**
2. **지식 & 메모리**
3. **제어 & 실행**
4. **검증**

여기서 `제어 & 실행` 단계에는 `Agentic RAG`와 `SDD`가 연결되어 있다.

즉, 에이전트는 단순 응답기가 아니라:

- 입력을 해석하고
- 지식과 기억을 찾고
- 실행하고
- 결과를 검증하는 구조다

### 5. A2A와 시스템 관점

메모에 나온 `A2A protocol`은 에이전트 간 상호작용을 염두에 둔 키워드다.

실무 감각으로는:

- 단일 에이전트가 모든 것을 처리하기보다
- 여러 에이전트가 역할을 나눌 가능성을 보여주는 개념

으로 볼 수 있다.

### 6. 검색의 세 축

메모는 검색도 데이터 성격에 따라 나눈다.

- **key**
  - `RDB`

- **의미**
  - `VectorDB`

- **관계성**
  - `Ontology / GraphDB`

이 구분이 중요한 이유는, 프로젝트에서 다루는 질문 유형에 따라 검색 저장소를 다르게 설계해야 하기 때문이다.

한 줄 감각은:

- 정확한 키 = RDB
- 의미 유사도 = VectorDB
- 관계 탐색 = GraphDB

### 한 줄 정리

- Agentic AI 프로젝트는 메모리 계층, 추론 비용, 검색 저장소, 검증 구조를 함께 설계해야 제대로 굴러간다.
